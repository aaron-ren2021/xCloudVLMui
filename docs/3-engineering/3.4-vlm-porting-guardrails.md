# 3.4 VLM 移植保護邊界（Guardrails）

**文件編號：** XCVLM-ENG-004  
**版本：** v1.0.0  
**日期：** 2026-04-21  
**狀態：** 生效中  
**適用範圍：** `xCloudVLMui` 針對 `air030` / 其他分支的 VLM 功能移植

---

## 1. 目標

本文件定義 VLM 功能移植時的「不可破壞區」與「禁止導入項目」，避免在接線過程中破壞既有 AGX Orin 主幹行為。

---

## 2. 絕對不能動（保護邊界）

以下區域視為 **高風險保護邊界**。  
除非有明確架構審核與回歸驗證，否則不得改動其核心行為。

### 2.1 Frontend 既有流程（不可破壞）

- `frontend/app/main/vlm/page.tsx` 既有能力必須保留：
- `iframe` 流程
- `standalone` 流程
- `VlmSimpleOverlay` 同步顯示流程

### 2.2 Backend API 契約（不可破壞）

- `backend/routers/vlm.py`
- `/api/vlm/status`
- `/api/vlm/diagnose`

### 2.3 Jetson / 容器啟動路徑（不可破壞）

- `docker-compose.yml` 既有 Jetson 路徑：
- `realsense-rtsp`
- `vlm-webui`
- `healthcheck`
- `/dev/video*` 映射

### 2.4 VLM 預設 patch 機制（不可破壞）

- `vlm-webui/patch-default-rtsp.py`
- minimal overlay 的 localStorage 同步機制

### 2.5 Nginx 路由與 port（不可破壞）

- 既有 `nginx` 路由與 port 映射

---

## 3. 禁止導入項目

以下內容 **禁止直接導入** 到主幹：

- `air030` 整套 `docker-compose.yml`
- `air030` 整套 `nginx.conf`
- `air030` 的 `/api/vlm/ws`
- `air030` 重寫版 `frontend/app/main/vlm/page.tsx`
- 任何會改變目前 RTSP/VLM 啟動順序的容器邏輯

---

## 4. 功能移植分類

## A. 可直接移植（Low Risk）

特徵：

- 純 TypeScript 型別
- 純計算邏輯
- 不依賴 DOM / stream transport 的 heuristic 函式
- 行為分類 mapping
- keypoint -> action label 規則

建議落點：

- `frontend/types/`
- `frontend/lib/`
- `frontend/hooks/`（純計算部分）

## B. 需要 adapter（Medium/High Risk）

常見檔案：

- `useYoloPose.ts`
- `useYoloTracker.ts`
- `useBehaviorDetector.ts`
- `useYolo.ts`（若為上游依賴）

原因：

- 假設特定 `<video>` ref
- 假設 stream lifecycle 由 `CameraStream` 管理
- 偵測 loop 與 websocket / raf 綁定
- overlay 座標系、解析度、縮放策略固定

處理原則：

- 不直接接管主幹 lifecycle
- 先做 adapter，再接主幹
- 不允許因新功能而改寫既有 `iframe/standalone/VlmSimpleOverlay` 主流程

## C. 禁止導入（Hard Block）

- 第 3 節列出的所有禁止項目

---

## 5. Adapter 介面建議

建議以介面隔離來源與渲染邏輯：

```ts
export type PeopleSourceKind = "structured" | "text" | "empty";

export interface PeopleAnalysisInput {
  rawPayload: unknown;
  capturedAt: string;
}

export interface PeopleAnalysisOutput {
  source: PeopleSourceKind;
  personCount: number;
  personInfos: Array<{
    gender: "male" | "female" | "unknown";
    action: "standing" | "sitting" | "walking" | "running" | "raising_hand" | "bending" | "squatting" | "unknown";
    genderConf: number;
    actionConf: number;
  }>;
  behaviors: Array<{
    type: string;
    risk: "critical" | "warning" | "safe" | "info";
    confidence: number;
  }>;
}

export interface PeopleAnalysisAdapter {
  parse(input: PeopleAnalysisInput): PeopleAnalysisOutput;
}
```

---

## 6. Code Review 準則

若 PR 觸及第 2 節保護邊界或第 3 節禁止導入項目，視為 **高風險 PR**：

- 必須標記 `High Risk`
- 必須附回歸驗證步驟（`/vlm`、RTSP、healthcheck、報告儲存）
- 未提供驗證證據不得 merge

---

## 7. 實施規則（必須遵守）

1. 移植前先分類（A/B/C）。
2. B 類先落 adapter，再接頁面。
3. 禁止整檔覆蓋主幹保護區。
4. 任何改動保護邊界都要附回退方案（tag/commit）與驗證證據。
